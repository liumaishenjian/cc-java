# S02 Picocli Java Print 证据（2026-07-29）

## 范围

- Stage: `S02 Model + Streaming CLI`
- Feature IDs: `BOOT-01`、`CLI-02`
- Current → Target: `BOOT-01 L1 → L2`、`CLI-02 L0 → L2`
- Reference Behavior Baseline: `R2026.03`
- Authorized Snapshot ID: `N/A - Not Used`
- Classification: Picocli 为 `Documented`；离线测试和真实模型结果为 `Observed`

## 实现

- Picocli 4.7.7 解析互斥 `--print`/`--stdio` 与标准帮助；
- `HeadlessRuntimeSession` 让 Print 与 stdio 共用 `AgentRuntime`、Session、取消和
  Tool Pipeline 装配；
- Print 只消费 `ModelTextDelta`，无 Delta 时回退一次聚合 `finalText`；
- `cc-java.ps1` 使用自身目录与根 POM，从任意当前目录构建并启动；
- `slf4j-nop` 只用于保持默认无内容日志策略，并避免框架无绑定警告污染 stderr。

## 验证

```powershell
.\mvnw.cmd -pl cc-java-cli -am test

powershell.exe -NoProfile -ExecutionPolicy Bypass -File `
  "E:\Java\cc-java\cc-java.ps1" --help

powershell.exe -NoProfile -ExecutionPolicy Bypass -File `
  "E:\Java\cc-java\cc-java.ps1" `
  --print "请只回复：print-clean"
```

本机结果：

- Reactor/CLI 离线测试通过；CLI 为 20/20，其中新增 8 项；
- 从 `C:\Windows\System32` 执行 `--help` 返回 0，显示两个互斥 Headless 模式；
- 从同一目录真实 `--print` 返回 `print-clean`，退出码 0；
- 修复日志绑定后没有 SLF4J 警告或其他 stderr 输出；
- Windows PowerShell 5.1 初次运行曾把 Java UTF-8 stdout 按本地代码页显示为乱码；
  脚本显式统一 `Console.InputEncoding`、`Console.OutputEncoding` 和
  `$OutputEncoding` 后，以真实模型复验得到正确中文 `你好，我是 cc-java。`；
- 第二次真实请求相较第一次明显更慢但最终成功，当时暴露出独立墙钟超时缺口；
  后续 ADR-026 与对应证据已经关闭该项。

真实配置、端点和 API Key 未写入命令输出、测试报告或本文。
