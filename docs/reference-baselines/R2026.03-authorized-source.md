## 6. S05 Permission Pipeline 机制观察

以下结论来自对权限类型、规则装载、决策器、审批队列、文件与进程权限检查以及统一 Tool
执行入口的受控只读研究；只记录可独立表达的机制，不记录参考函数体、私有类型名、文件
布局、错误文案或实现常量。

| 分类 | 结论 |
| --- | --- |
| Observed | 权限决策把 `allow / ask / deny` 与决定原因、规则来源和可选更新范围分开表达；`ask` 必须由交互或受信控制面收敛 |
| Observed | 规则至少可以按 Tool 及可选内容范围匹配，并保留内存 Session 与磁盘配置等来源；显式 deny 和需强制询问的安全检查早于普通 allow 与模式放行 |
| Observed | 模式与规则不是同一概念；“接受编辑”只为受控编辑路径提供快捷允许，保护性检查仍可要求审批，非交互入口不能展示请求时安全拒绝 |
| Observed | Session approval 通过对当前权限上下文追加有界规则实现，生命周期止于当前进程；批准一次不会自动批准后续调用 |
| Observed | 内置与外部 Tool 在执行层复用同一权限检查和结果归一化入口，来源信息参与诊断或规则匹配但不构成绕过凭据 |
| Observed | 交互审批存在多个可能竞争的决定来源，并使用一次性收敛与取消清理避免过期决定执行 Tool |
| Observed | 重复拒绝会被显式计数并在达到阈值后改变恢复策略，成功执行可打断连续拒绝；具体阈值不作为本项目契约输入 |
| Inferred | Java S05 应把可信 Hard Denial、显式规则、模式默认、Session Grant 与 Approval 组合成一个类型化策略内核，并由 Core/Pipeline 发布权威生命周期 |
| Unknown | 当前快照对应的准确发行版本、规则跨版本兼容、全部 Managed Policy 语义以及各种外部 Surface 的稳定协议 |

本项目的采纳和偏离见
[ADR-038](../adr/ADR-038-s05-authorized-permission-study.md)；独立 S05 契约见
[ADR-039](../adr/ADR-039-s05-permission-pipeline.md)。参考实现不作为测试 Oracle。

## 7. S06 Session + Checkpoint 机制观察

以下结论来自对持久 Transcript、Session 身份/Workspace 归属、恢复/分叉、活跃所有权、
未配对 Tool、文件修改历史与显式恢复的受控只读研究；只记录可独立表达的机制，不记录参考
函数体、私有名称、文件布局、错误文案、常量或内部数据格式。

| 分类 | 结论 |
| --- | --- |
| Observed | 持久对话保存聚合语义记录，而不是把模型流的每个 token 当作规范 Transcript 条目；低价值进度展示与规范历史分离 |
| Observed | Session 身份、Workspace 归属和元数据是独立职责；Resume 复用原 Session，Fork 创建新身份并保留来源关系，后续追加不修改原 Session |
| Observed | 恢复会重建有效规范链并识别缺少对应结果的 Tool 使用；中断不能被解释为可安全再次执行副作用 |
| Observed | 活跃 Session 使用显式所有权/进程登记，并区分仍活跃与陈旧状态 |
| Observed | 文件恢复基于修改前状态或“不存在”标记，独立于 Git；差异检查与恢复由显式用户动作触发 |
| Inferred | Java S06 应把可忽略的观察 sink 与副作用前必须成功的 durable journal 分离，并以 started/completed、write-ahead checkpoint 和 compare-before-restore 建立 Fail Closed 恢复 Gate |
| Unknown | 准确发行版本、内部格式稳定性、跨平台/网络文件系统锁语义、保留/迁移策略和全部副作用恢复覆盖范围 |

采纳边界见
[ADR-040](../adr/ADR-040-s06-authorized-session-checkpoint-study.md)；独立 S06 契约见
[ADR-041](../adr/ADR-041-s06-session-checkpoint.md)。参考内部格式不进入项目，也不作为测试 Oracle。

## 8. S07 Context Engineering + File Memory 机制观察

以下结论来自对请求前 Context 组装、容量减压、Tool 历史清理、滚动/全量摘要、文件记忆索引与
相关召回编排的受控只读研究；只记录可独立表达的职责、状态转换和失败边界。

| 分类 | 结论 |
| --- | --- |
| Observed | 模型请求所见 Context 与持久会话事实分离；压缩服务后续请求，不要求改写规范 Transcript |
| Observed | 大载荷缩减、旧 Tool 输出清理、滚动记忆和全量摘要由不同职责承担，并按压力条件选择；Tool 协议关系保持完整 |
| Observed | 文件记忆分离存储、入口索引、可发现目录、相关召回和请求投影；查询准备可并行，召回失败或迟到不阻断主请求 |
| Inferred | Java S07 应采用 Canonical Transcript/Projection 分离、条件式 C1-C4、M1-M5 文件记忆和 ready-only 零等待消费；失败候选不提交，迟到结果不注入已发送请求 |
| Unknown | 准确发行版本、内部 Prompt/阈值/评分/布局/格式、全平台时序保证、保留迁移与多主机一致性 |

采纳边界见 [ADR-042](../adr/ADR-042-s07-authorized-context-memory-study.md)；独立 Context 与
Memory 契约见 [ADR-043](../adr/ADR-043-s07-context-projection-compaction.md)和
[ADR-044](../adr/ADR-044-s07-file-memory-prefetch.md)。本项目的命名、文件格式和数值上限均为
独立设计，参考实现不作为测试 Oracle。
