# ADR-020：隔离未核验参考材料，恢复可审计的公开来源链

- Status: Accepted
- Date: 2026-07-28
- Decision Owners: 项目维护者
- Scope: S00-S15 的来源、研究与实现边界
- Capability IDs: 全部；本 ADR 不提升任何 Capability Level
- Quarantined Snapshot: `UNVERIFIED-SRC-2026-03-31-A`
- Supersedes: ADR-018 的授权研究例外、ADR-019 的参考结论采纳决定

## 背景

仓库曾把一组位于仓库外的本地字节登记为 `AUTH-SRC-2026-03-31-A`，并仅依据一次
对话中的维护者说明将其视为“已授权学习材料”。现有证据不能独立核验：

- 材料的准确来源、Commit、Tag、版本和完整性；
- 本地字节与候选上游仓库的对应关系；
- 适用于这些字节的许可证或权利人；
- 学习、派生实现、公开研究结论和再发布分别获得了何种授权；
- 授权期限、撤回方式和可审计的授权文件。

这不等于认定材料违法或维护者说明不真实；它只表示当前仓库没有足够证据把“已授权”
作为可复现的工程事实。继续把该材料作为设计输入，会使学习证据、开源边界和后续实现
来源无法被外部贡献者独立审计。

## 决策

### 1. 将材料降级并隔离

原快照改记为 `UNVERIFIED-SRC-2026-03-31-A`，状态为 `QUARANTINED`。

在新的授权证据 ADR 被接受前：

- 不读取、搜索、分析或继续使用该材料；
- 不把其中观察或推断出的机制作为 PRD、技术设计、矩阵、测试或代码输入；
- 不把它作为依赖、子模块、Fixture、Golden Output、发布物或对照 Oracle；
- 只保留最小的来源不确定性、字节指纹和隔离决定，避免把研究内容继续传播到活动文档。

隔离记录见
[R2026.03 未核验参考材料登记](../reference-baselines/R2026.03-unverified-source.md)。

### 2. 活动基线只使用可审计输入

当前活动设计输入限定为：

1. 本项目自己的 PRD、ADR、验收场景和测试；
2. 有 URL、访问日期和分类的官方公开文档；
3. 可独立复现的黑盒观察；
4. 明确标记为 `Inferred` 的公开二手研究问题。

公开页面没有归档或内容指纹时仍然只能形成临时 `Documented` 结论；达到 L3 仍需
版本化官方依据或可重放黑盒证据。

### 3. 撤销不能由公开来源独立支撑的活动结论

- ADR-018 保留为历史记录，但其“已授权研究例外”被本 ADR 取代；
- ADR-019 保留为历史记录，但不再是 S07 的活动设计输入；
- 仅由该快照产生的 `CTX-17`、`CTX-18` 从活动 Capability Matrix 删除；
- 其他 Context 能力仅按公开来源保留，S07 启动时必须重新研究、重新写 ADR，并用独立
  场景决定具体 Reducer、记忆策略和阈值，不能沿用被隔离材料中的结论。

删除 Capability ID 是纠正基线来源，不代表实现能力回退。S01 的 19 个 L1 不变。

### 4. 修正 S01 的实现来源

S01 代码在该材料被登记前已经完成，并由本项目 Fake Model、Fake Tool、协议测试和
Commit-scoped 构建证明。S01 的证据与差距报告统一记录：

```text
Authorized Snapshot ID: N/A - Not Used
```

后续对 S01 的比较性阅读不能倒灌成实现来源，也不能提升 S01 的 Capability Level。

## 重新启用参考材料的条件

只有同时具备以下证据，才能通过新的 ADR 重新评估：

1. 可核验的来源主体和材料身份；
2. 精确 Revision 或能够稳定映射到字节集合的 Manifest；
3. 适用许可证或权利人的书面授权依据；
4. 明确的使用范围、期限、撤回条件和公开研究边界；
5. 对已经产生的研究结论进行逐项重新验证；
6. 法律或授权不确定项保持 `Unknown`，且不靠推断补齐。

满足条件也不会自动允许复制或逐行翻译；Java 实现仍必须由本项目需求、独立契约和测试解释。

## 结果

正面结果：

- 活动需求和设计恢复为可由仓库内证据审计的来源链；
- S01 的实现证据不再与后续研究材料混淆；
- 后续贡献者不会误把未核验材料当作已授权或可复用源码；
- 保留通过合法、可核验材料开展受控研究的未来通道。

成本：

- 需要在 S07 到来时重新验证 Context 设计，不能复用 ADR-019 的研究结论；
- Capability 总数由 195 调整为 193，历史看板数字需要同步更新；
- 与成熟产品的深入比较暂时依赖官方文档和独立黑盒观察。

## 被否决的方案

### 继续依赖维护者口头确认

口头确认可以表达意图，但不能让外部贡献者复现材料身份、授权范围和权利边界。

### 删除所有历史记录

删除会掩盖设计演进。保留 Superseded ADR 和最小隔离登记，更利于审计为什么停止使用。

### 把不确定材料改称“仅学习”后继续使用

“仅学习”“不商用”或“仓库外保存”不会自动解决来源和授权证据缺失。
