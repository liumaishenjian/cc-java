# ADR-022：按维护者授权确认恢复参考源码的受控学习

- Status: Accepted
- Date: 2026-07-29
- Decision Owners: 项目维护者
- Scope: S00-S15 的来源研究边界
- Capability IDs: 全部；本 ADR 不提升任何 Capability Level
- Authorized Snapshot: `AUTH-SRC-2026-07-29-A`
- Supersedes: ADR-020 对同一组本地字节的持续隔离决定

## 背景

ADR-020 在无法从仓库内独立核验授权时，选择了最保守的隔离。项目维护者随后再次明确：
本地材料已经获得学习授权，并要求项目通过受控源码研究理解成熟机制，而不是在缺少参照
和评测的情况下从头试错。

学习授权、源码许可证、复制权和再发布权是不同问题。本项目可以接受维护者对学习权限的
明确确认，同时继续把准确 Revision、许可证、权利人及公开再使用权标记为 `Unknown`，
并用技术和流程边界禁止参考表达进入仓库。

## 决策

1. 将同一组本地字节登记为
   [`AUTH-SRC-2026-07-29-A`](../reference-baselines/R2026.03-authorized-source.md)，
   允许在仓库外路径进行只读、受控的机制研究。
2. ADR-020 和
   [`UNVERIFIED-SRC-2026-03-31-A`](../reference-baselines/R2026.03-unverified-source.md)
   保留为历史审计记录，但不再禁止维护者已授权的本次研究。
3. 研究只能提炼职责、状态、不变量、失败恢复和验证方法；不得复制或逐行翻译函数体、
   Prompt、注释、错误文案、私有类型、文件布局、实现常量或内部格式。
4. 授权材料不得进入本仓库、依赖、子模块、Fixture、Golden Output 或发布物。
5. 每个被采纳的机制必须由单独 ADR 转换为本项目可解释的需求、独立契约和可证伪测试；
   参考源码本身不作为测试 Oracle。
6. 对外声明必须区分“从授权材料观察到的机制”“本项目的独立设计”和“已经验证的实现”。

## 为什么可以在仍有 Unknown 时研究

本 ADR 不把未知许可证解释为允许再发布，也不把候选上游 URL 解释为准确来源证明。
维护者确认的范围仅是学习；快照指纹固定研究对象，严格的非复制边界限制输出。若未来要
分发参考字节、复用代码或形成派生作品，则必须取得并记录新的、相应范围的依据。

## 对历史决策的影响

- ADR-018 继续作为受控研究方法的历史来源，其流程原则重新生效，但活动 Snapshot ID
  以本 ADR 为准；
- ADR-019 不会自动恢复为 S07 的最终设计，S07 仍需对具体结论重新研究和采纳；
- ADR-020 改为 Superseded，说明曾经为什么暂停以及由什么新证据恢复；
- S01 的实现来源仍是 `N/A - Not Used`，不会因后续比较阅读而被追溯改写。

## 验证与停止条件

每次研究必须记录 Snapshot ID、结论分类和采纳 ADR。若授权范围出现疑问、快照发生变化、
研究输出无法与参考表达分离，立即停止并恢复隔离。本 ADR 不表示任何产品能力已实现，
也不提升功能矩阵等级。
