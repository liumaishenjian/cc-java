# ADR-018：受控研究已授权参考源码，并保持 Java 独立重实现

- Status: Accepted
- Date: 2026-07-28
- Decision Owners: 项目维护者
- Scope: S00-S15 学习方法与证据链
- Capability IDs: 全部；本 ADR 不直接提升任何 Capability Level
- Authorized Snapshot: `AUTH-SRC-2026-03-31-A`

## 背景

`cc-java` 的目标不是只根据功能名称重新试错，而是理解成熟 Coding Agent Harness
已经采用的职责划分、状态转换、失败恢复和验证方法，再以独立 Java 契约实现。

项目最初的文档只允许公开文档、公开接口和黑盒行为作为参考输入。这能降低复制风险，
但无法完整支持维护者已经取得合法学习授权后的源码研究目标，也容易让阶段计划停留在
“知道要做什么功能”，却没有记录成熟机制为什么这样设计。

2026-07-28，项目维护者明确确认已取得本地参考源码的学习授权。本地材料位于仓库外的
隔离目录，不进入 `cc-java` 的 Git 历史、依赖、测试 Fixture、Golden Output 或发布物。
快照的可复现身份、已知缺失和使用边界记录在
[授权参考源码基线](../reference-baselines/R2026.03-authorized-source.md)。

## 决策

项目采用“双基线、四类来源结论、七道 Gate”的参考驱动学习方法。

### 双基线

1. [`R2026.03`](../reference-baselines/R2026.03-public-behavior.md)：登记官方文档、
   公开接口和独立黑盒观察槽位的临时行为基线；当前黑盒观察包为空；
2. `AUTH-SRC-2026-03-31-A`：仅用于受控机制研究的授权源码快照。

行为基线定义可以独立验收的需求。授权源码快照帮助解释子系统职责、状态机、不变量、
失败路径和验证方法，但不自动成为需求，也不自动证明某个实现正确。

`R2026.03` 当前只固定来源清单，在线页面内容尚未归档或建立内容指纹；没有独立黑盒
观察包的能力不能据此宣称达到 L3。精确限制记录在公开行为基线文档中。

### 四类来源结论

研究记录必须明确区分：

- `Documented`：访问当日由官方公开文档说明、但尚未经过独立黑盒观察的行为；
- `Observed`：当前输入可以直接确认；用于公开行为基线时指独立黑盒观察，用于授权源码
  基线时指快照中直接确认的机制；
- `Inferred`：根据多个调用点或状态关系作出的解释；
- `Unknown`：因快照缺失、Revision 不明或无法运行而不能确认的内容。

授权源码的机制结论只使用 `Observed / Inferred / Unknown`；`Documented` 专用于公开
官方资料，不能伪装成黑盒观察。

对外能力声明还必须区分：

- 从参考材料观察到的机制；
- `cc-java` 选择的独立 Java 设计；
- 已由测试、Demo 或 Eval 证明的实现。

### 七道 Gate

每个 Stage 统一执行：

```text
G0 Provenance
→ G1 Scope
→ G2 Research + ADR
→ G3 Independent Java Implementation
→ G4 Verification
→ G5 Reproducible Demo
→ G6 Exit Reconciliation
```

具体字段和退出检查见
[Stage 证据包模板](../templates/stage-evidence-package.md)。

授权源码研究结论不得直接进入代码。每个 Stage 在采纳结论前，必须通过一篇单独的
“参考结论采纳 ADR”明确以下内容；Stage 设计 ADR 可以与其互链，但不能替代：

1. 正在重现的独立行为；
2. 参考机制中被采纳的职责、不变量和失败语义；
3. 本项目的 Java 契约、命名和模块边界；
4. 没有采纳的部分及原因；
5. 能够证伪当前理解的测试和度量。

## 独立重实现边界

允许记录和使用：

- 子系统职责与依赖方向；
- 状态迁移、终止条件和恢复策略；
- 算法类别、决策顺序和协议不变量；
- 可观察行为、失败模式和评测方法。

禁止复制或逐行翻译：

- 函数体、内部 Prompt、注释和错误文案；
- 私有类型名、文件布局和实现常量；
- 内部 Session、Hook、配置或遥测格式；
- 参考源码文本、私有数据或生成物形式的 Golden Output。

Java 实现必须能够从本项目 PRD、技术设计和 ADR 独立解释。Spring AI、Provider SDK
或参考项目类型都不得泄漏到 Domain/Core。

## 对现有阶段路线的影响

- 保留 S01-S15 的总体顺序；
- S01 继续作为 Runtime Kernel 学习骨架，不因本 ADR 追溯性改变代码；
- S03-S04 先建立类型化 Tool Result 限制和外置元数据；
- S06 为 S07 建立 Canonical Transcript、稳定消息 ID、协议回合和投影决策持久化；
- S07 按渐进式 Context Reduction 决策图实现，不把“四层”误写成固定串行算法；
- S08 扩展 Instructions/Settings 后，必须重新验证 Context 重注入；
- S12 和 S14 使用内部检查点降低一次性交付范围；
- S14 将早期 Stage 已存在的专项 Eval 产品化，而不是第一次引入评测；
- S15 仍只在参考可比基线和可重复 Eval 成立后进入主线。

## 结果

正面结果：

- 每个实现任务都有可追踪的成熟机制参考；
- 参考材料中的未知和缺失不会被包装成确定事实；
- Java 代码仍保持独立契约、可解释性和可发布边界；
- “谁验证”由确定性测试、行为对照和 Eval 回答，而不是由参考源码权威性回答。

成本与限制：

- 每个 Stage 在实现前增加研究记录和 ADR 成本；
- 快照升级时必须重新计算指纹并记录行为差异；
- 当前快照缺少 Git 元数据、构建清单和正式测试，不能验证其精确版本和运行正确性；
- 任何授权范围变化都可能暂停相关研究。

## 被否决的方案

### 仅保留公开资料研究

无法满足项目通过授权源码理解成熟实现机制的核心学习目标。

### 将参考源码逐文件翻译成 Java

会把语言转换误当作架构理解，并带来复制、维护和发布风险。

### 把参考源码当作测试 Oracle

当前材料无法复现或验证构建，Revision 不明且没有正式测试套件；即使材料完整，源码表达
也不应成为本项目断言。测试必须来自独立行为、不变量和故障场景。

## 后续要求

1. 使用 `AUTH-SRC-2026-03-31-A` 的 Stage 必须在证据包中引用该 Snapshot ID；
   未使用授权材料的任务写 `N/A - Not Used`，不得制造虚假来源关联；
2. 研究笔记只保存必要的机制抽象和结论置信度；
3. Source Baseline、PRD、技术设计、功能矩阵和 README 的能力声明必须保持一致；
4. 本 ADR 不代表 S02 或 S07 已实现，也不提升任何矩阵等级。
