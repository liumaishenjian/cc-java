## 已审计的 G3 实现

- 受限 `/model` 和 `/permissions mode` 的内存 Session overlay 事务：仅启动时已装配模型和 `DEFAULT`、`PLAN`、`ACCEPT_EDITS`，保留 CLI precedence，并经 LKG CAS 与 RuntimeScope idle 原子边界提交。
- `/permissions` 只读投影实际 Runtime mode 与 Settings-derived STARTUP rule provenance，不回显 selector、规则原文或 Runtime grants。
- 显式 `/compact`：支持最多 16 个锚点，经 S07 Gate 生成一次性下一 Run 首个模型请求 Projection；不改 Canonical/JSONL/Checkpoint，失败、取消或来源变化不提交。
- `/context`、doctor、stdio v0 与封闭 React/Ink Slash 的类型化白名单投影；commandId 保持有界且每 ID 仅一个终态。
- recovery-gated `/resume <session-id>`：Java Application 仅在 idle 时调用既有 S06 writable Resume；Workspace、writer lease、fence、incomplete side effect 与 Checkpoint recovery Gate 任一拒绝、取消或竞争均保持旧 Session。成功只投影前后 Session ID，stdio/TUI 对未知或不一致结果 fail closed；不自动重放 Tool 或副作用。
- G3-E 受控输入：Enter 换行、Ctrl+Enter 提交，8,192 Unicode code point 缓冲、每 Session 内存历史 100/草稿恢复、封闭补全最多 32。
- G3-E steering：Java stdio 内存 FIFO 最多 100 条，当前 Run 唯一终态后才启动下一 Run；取消、clear、成功 resume、transport failure、shutdown/close 与第 101 条拒绝均清理对应瞬态状态，未发送正文不写 Canonical/JSONL/Checkpoint。
