## Accepted 后仍存在的 gap

1. **Managed/Auto 未生产接入**：`PERM-05` 与 `CFG-07` 保持 L0；现有 deterministic baseline/provenance 不能描述为稳定 Managed Policy 或 Auto Mode。
2. **JVM 内网络不受强制**：Hook HTTP、MCP/Plugin remote 不经过 `ExecutionBackend`；需要统一 `NetworkAccessPort`/egress broker 后才能提升，`HOOK-10` 保持 L1。
3. **native Windows file/network 未实现**：当前只证明 process/env/cleanup B，file/network U；WSL2 Linux A 不替代 native Windows A。
4. **macOS 未真实验证**：无真实主机，只能保留 C/U。
5. **bubblewrap 能力边界**：固定验证版本为 0.4.0；不声称 seccomp、新版 `--clearenv` 或所有内核/WSL 配置等价。
6. **Container 供应链与生命周期**：pinned digest 只固定本次验证身份；镜像签名、SBOM、漏洞治理、更新与跨平台发行属于后续范围，`SEC-11` 保持 L0。
7. **S13 退出时稳定外部能力尚未开始**：OAuth、稳定机器协议、SDK/Daemon、Export/Retention/Migration、Marketplace 与签名不属于 S13。该历史结论描述 S13 验收时点；S14 当前已是 IN_PROGRESS、Stage Exit OPEN。

## 参考仍然更强之处

- 成熟实现可在更多原生平台提供文件/网络强制和受管策略分发。
- 成熟实现可把 JVM/宿主进程内网络也纳入统一 egress 控制。
- 成熟供应链体系可提供签名、撤销、SBOM、更新和兼容治理。

这些差距不阻塞已冻结范围的 S13 Accepted，但任何后续能力提升都必须重新完成对应 Stage/Gate 和真实平台证据。
