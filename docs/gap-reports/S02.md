## Reliability

- 离线回归没有失败；尚未建立跨版本、跨模型的长期 flaky rate；
- 可见 Delta 之后不自动重试，避免重复文本；可重试错误只有单一 Core 所有者并有次数、
  Deadline 双重上限；
- `LENGTH` 明确停止并映射非零退出码，不把截断响应报告为完整成功；
- 客户端取消在固定 Spike 中约 1.25 秒返回且无 late signal；服务端计算是否立即终止
  仍为 `Unknown`；
- Prompt/完整内容默认不写日志，Print 把 Assistant 文本与状态分流；Ollama 不提供
  可验证货币成本时不伪造 cost；
- Turn/Tool 耗时可由确定性事件时间戳推导；Micrometer/OTel Export 仍属于 S14；
- 真实限流、断网恢复和原生 Windows Terminal 的版本化可靠性统计尚未建立。

## Closed S02 hardening risks

1. 流 Subscriber 已从无界请求/队列改为容量 2 的队列与逐项 `request(1)`。
2. 单回合保留内容共享 8 MiB UTF-8 上限，并限制最多 128 个不同 Tool Call；超限在当前
   Delta 发布前取消，结构化为不可重试 `RESPONSE_LIMIT_EXCEEDED`，Runtime 映射
   `MODEL_OUTPUT_LIMIT_REACHED`。
3. 同一 Chunk 重复 Call ID 按 `INVALID_RESPONSE` 拒绝，跨 Chunk 相同 ID 仍可合并；
   冲突 Finish Reason、空 `tool_calls` 和无效 Usage 也有独立结构化分类。

终端控制序列风险已在 S02 加固：Renderer 对所有不可信终端字段剥离
ESC/CSI/OSC/DCS/C0/C1，保留 Assistant 的 LF/Tab 并把状态字段折叠为单行；Print 与
Interactive 共用契约。相应回归还验证按模型回合跟踪 Delta，避免早期 Tool 回合的 Delta
吞掉最终回合聚合文本。

剩余边界是 Provider SDK 在 Adapter 收到 `ChatResponse` 前已分配的单个巨大对象，本地
retained cap 无法阻止这次先行分配；Adapter 会拒绝该响应，不继续保留或发布当前 Delta。

## What the reference still does better

1. `[Documented；固定版本黑盒结果 Unknown]` 成熟 Coding Agent 提供真实仓库读取、
   修改、命令执行、审批和隔离；S02 仍是模型与终端切片，不能完成编码任务。
2. `[Documented + Inferred]` 成熟 CLI 具有更完整的终端历史、多行粘贴、运行中
   steering、稳定 headless 协议和跨平台分发；S02 只验证基础 JLine/Print，真实
   Windows Terminal 人工结果仍为 `Unknown`。
3. `[Documented + Inferred]` 生产模型层通常覆盖多个 Provider、Fallback、真实限流、
   统计/成本、Telemetry 与跨版本兼容；S02 只验证 Ollama 0.32.4 和一个本地模型。
4. `[Documented]` 成熟 Harness 提供持久 Session、恢复/分叉、Context 压缩、
   Instructions/Settings、Hooks、MCP、Skills、Subagent 和 Sandbox；S02 仍只有进程内
   Session 与稳定 System Context。

本报告没有把任何未核验参考源码用作这些结论的证据。未固定产品版本和不可重放的行为
保持 `Unknown`，不伪造成已经完成的黑盒对照。

## What cc-java now does differently

1. 直接使用 `StreamingChatModel` Adapter，而不是让 `ChatClient`/Advisor 自动运行
   Tool Loop；Runtime 仍唯一拥有预算、重试、取消和终态。
2. 用 Schema-only Callback 提供 Tool 定义，并用不可执行哨兵证明 Spring AI 没有执行
   Agent Tool。
3. Reactor、Spring AI 和 Ollama 类型留在模型模块；Domain/Core 只看到项目自有
   Observer、Delta、Usage、Finish Reason 和结构化错误。
4. Spring AI 内部重试为 0；Core 只在没有可见 Delta 时做有界重试，避免重复输出。
5. 模型名必须显式指定，Ollama 不要求云 API Key；Usage 或 cost 不可用时保留缺省，
   不用 0 冒充测量。
6. Print 强制无 ANSI并分离 stdout/stderr；non-TTY 不进入伪交互，也不等待输入。

## Accepted deviations

- S02 选择本地 Ollama 作为首 Provider，不声称云 Provider 已验证；
- 输出长度达到上限时选择有界停止，自动续写与更成熟恢复策略延后到 S14；
- 自动化 PTY 被正确降级为 non-TTY；真实 Windows Terminal 人工体验保持 `Unknown`；
- S02 不提供稳定 JSON/JSONL 机器协议，Print 只承诺当前人类可读文本和稳定退出码；
- Token Usage 可记录，货币成本不可验证时缺省。
