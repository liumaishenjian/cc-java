# S06 Session + Checkpoint 差距报告

## 已理解并验证

S06 已把进程内 Session 提升为项目自有、版本化的 append-only semantic JSONL：聚合 User/
Assistant、Tool durable 状态、Run 终态、Workspace-aware metadata 和 lineage 能够经 Create、Continue、
Resume、Fork、Inspect 恢复。文件 Adapter 使用本机 `FileLock` 保证单 Writer，损坏 Schema、超限、
Workspace 错配、损坏尾部和未完成 Tool 均有确定性分类；任何有副作用操作都绝不自动重放。

写 Tool 通过统一 Pipeline 在执行前创建 ordinary-file Checkpoint，并按
`checkpoint.created → tool.started → execute once → checkpoint.completed → tool.completed` 提交。
Checkpoint metadata 显式记录 prepared/uncertain/completed/undo phase；Diff 有界且只投影相对路径；
Undo 要求 Writer、非 fenced、无活动 Run、具体 Checkpoint 的独立显式确认及最终 digest/NOFOLLOW/
realpath 重检。React/Ink 只通过受控 stdio 完成 list/diff/逐项确认 Undo。

## 仍弱于成熟 Harness 的能力

- `SESSION-08` 仅达到 L1：只实现本机 OS `FileLock` 与只读 Inspect，没有 PID/启动身份、heartbeat、
  stale lease 判断、主动 reclaim、网络文件系统或多主机一致性；这些属于 S14；
- JSONL/stdout v0 是内部协议，没有稳定 Export、Retention、Clear、SQLite、跨 major Migration 或兼容
  支持；`SESSION-12/13` 仍为 L0，属于 S14；
- Checkpoint 仅支持单个普通文件，不能恢复目录树、Symlink/Junction、Shell、进程、网络、远端、环境变量
  或权限变更，也不替代 Git；更广副作用隔离属于 S13；
- Metadata 与 JSONL 不能原子提交，因此 `*_JOURNAL_UNCERTAIN` 需要 Inspect/人工处理；S06 不自动猜测、
  修复或迁移这些状态；
- Session permission grant 与拒绝计数当前仍是进程内状态，没有声明持久 Permission Settings；S08 再定义
  User/Project/Local/Managed 配置层；
- S07 Context Engineering、压缩、摘要和 Token 压力治理未实现；恢复的是 canonical history，不表示长会话
  已具备生产级 Context 管理；
- `EVAL-02` 达到 S06 L2 的确定性 Behavior Replay，但尚无 S14 统一数据集、报告、跨版本回放兼容和长期
  质量指标；
- 当前没有 OS Sandbox；FileLock、Permission、Checkpoint、WorkspaceGuard 和进程树清理都不能描述为
  文件/进程/网络隔离。

## 下一步

S06 完成后按矩阵进入 S07 Context Engineering 的授权机制研究与启动 Gate：先固定 Token Budget、
消息淘汰、摘要/压缩、防抖和可证伪长会话 Eval，不修改 S06 journal 语义，也不提前实现 S08 Settings
或 S14 稳定迁移协议。
