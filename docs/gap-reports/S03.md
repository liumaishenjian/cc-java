## 已独立实现

- `list_files`：稳定协议路径、glob、深度/条目限制、不跟随目录链接；
- `search_text`：字面搜索、路径/行号/片段、文件数/扫描字节/匹配限制；
- `read_file`：1-based 行分页、严格 UTF-8/BOM、文件大小和 continuation；
- `git_status`：分支、staged/unstaged/untracked 安全摘要；
- `git_diff`：staged/unstaged 枚举模式、Guard pathspec、固定只读 ProcessBuilder；
- WorkspaceGuard：绝对/UNC/drive-relative/traversal、realpath containment、Symlink/Junction；
- 固定敏感路径策略与安全模板例外；
- Tool 语义 metadata 和 Pipeline 最终 Unicode 字符 ceiling；
- 根 `AGENTS.md` 单层加载及不得提权测试；
- WorkspaceSnapshot；
- stdio/TUI Tool started/completed/failed 脱敏投影；
- Scripted Model 五 Tool E2E、安全错误后恢复和 Windows Junction 实证。

## 相比成熟参考仍缺失

| 差距 | 影响 | 后续 Stage |
| --- | --- | --- |
| Search 不支持正则、ignore 语义或结构化代码索引 | 大仓库搜索精度和效率有限 | S14 / Code Intelligence |
| list/search continuation 只有安全重试提示，不是稳定游标 | 超大结果集需要模型缩小 path/glob | S07/S14 |
| Git rename 的 C-style quoted path 只支持保守子集 | 极端特殊文件名可能被过滤 | S14 跨平台兼容 |
| Tool 没有执行中取消和统一 timeout | 文件读通常短，但超慢网络文件系统仍缺控制 | S04 |
| 根指令只支持 Workspace 根一层 | 子目录作用域和用户级规则缺失 | S08 |
| stdio v0 仍非稳定公共协议 | 外部 Client 不应依赖兼容性 | S14 |
| WorkspaceGuard 不是 OS Sandbox | 不能隔离未来获批进程或用户账户权限 | S13 |
| 没有自动 Context 压缩 | 长 Session 只靠单结果硬限制 | S07 |

## 独立偏离

- S03 搜索只接受字面文本，避免在无 Tool timeout 的阶段开放任意正则；
- 不使用通用 Shell 或第三方 grep/git 库；
- 项目指令采用通用根 `AGENTS.md` 最小约定，不复制某产品完整配置机制；
- 敏感路径策略在 S08 前固定且不能由 Prompt 放宽；
- Git 错误不返回原始 stderr，牺牲部分诊断细节以守住默认隐私边界。

## 风险

- 文件系统大小写语义、Symlink 权限和 Git 路径 quoting 在不同 OS 上仍需继续回归；
- 当前测试覆盖 Windows NTFS Junction，本轮尚无独立 Linux CI 结果；
- 真实 Provider 是否稳定选择全部五个 Tool 属于模型/Provider 兼容性，不由离线 E2E 自动证明；
- 固定敏感文件名不可能穷举所有秘密，用户仍不应在含未知秘密的不可信仓库中盲目运行。
