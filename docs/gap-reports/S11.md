## 参考仍更强之处

1. 成熟实现已有实际 Skill discovery/invocation、插件目录/组件和长期运行经验；cc-java 目前只有独立设计。
2. 参考生态包含更丰富的远程发现、市场、更新、签名/治理或多运行时组件；S11 明确不实现这些。
3. 参考实现的选择质量、跨压缩恢复、插件安装并发和跨平台故障上界尚未形成 cc-java 对照数据。

## cc-java 的独立偏离

1. `allowed-tools` 固定为 runtime visibility 与 Skill allowlist 的纯收窄交集，Permission/Grant 不静态化，每个调用重新评估。
2. 禁止 nested/reentrant Skill；单 Run 每个不同 Skill 至多一次，Scope/Hook 只从正文成功投影持续到唯一终态，Resume 无活动 Run 不恢复。
3. Plugin Tool Provider 只允许宿主预注册 factory并返回有 lease/close 的 Contribution；manifest 不构造 ToolDefinition/ToolSource，S11 明确拒绝任意 JAR/Class/ServiceLoader/native/script。
4. Plugin 以 immutable Session snapshot、目录-only 原子 staged install 和 quiescing uninstall 避免运行中语义漂移。
5. Session journal 只持久化 Skill digest/调用事实，正文/资源保持短生命周期 Projection。
