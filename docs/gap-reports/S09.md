# S09 Hooks 差距报告

更新时间：2026-08-08

## 已完成的第一批学习切片

- `HOOK-02` / `HOOK-03`：Core Hook Coordinator 与 Tool Pipeline Pre/Post 接入达到 L1；
- `HOOK-04` / `HOOK-05` / `HOOK-06`：InMemory/File Session、Agent Runtime 的 Session/Run/Prompt/Model
  生命周期与 ASK Permission 收敛达到 L1；Hard Denial 不能被 Hook 覆盖；
- `HOOK-09`：CLI 边缘固定 argv + JSON stdin/stdout Command Adapter 达到 L1；超时、取消、输出上限、
  非零退出和无效协议均回到 Core 失败策略；
- `HOOK-12`：事件 + 有界主体正则 Matcher 达到 L1；
- `HOOK-13`：有界并发、超时、取消、未信任和 Fail-Open/Fail-Closed 达到 L1；
- ADR-054 已提供来源枚举、长度前缀 SHA-256 指纹与项目 Hook 的显式 Workspace/批准 Gate；
  未接入持久配置文件或 Trust UI，不能把它描述成可用的 Settings 产品能力；
- 所有测试使用项目自有协议和 Fake，不把授权源码或外部产品文本作为 Golden Output。

## 仍然缺失

1. S08 user/project/local Hook 配置 schema、来源合并、Trust Store 持久化和诊断命令；当前只有独立
   fingerprint/trust 核心 Gate；
2. Pre/Post Compact 与 Context Projection 的正式注入和可追踪生命周期；
3. Command Adapter 的生产 Composition Root、配置加载与 TUI/stdio 活动摘要；
4. 仅 loopback 的 HTTP Handler；远程网络、认证和 OS Sandbox 延后 S13；
5. Prompt/Agent/Sub-Agent Hook（S12/S15）与稳定外部 Hook 协议（S14）。

## 采纳偏离

第一切片不允许 Handler 改写 Tool Input，也不允许 Hook 重新进入模型或 Tool Loop。Post Tool 的
阻断意见被降级为继续；这是保护已完成副作用和统一 Pipeline 的有意偏离，需在后续对照中保持。

## 下一验证

下一步完成 Hook Settings/Trust、Compact 与 Command Adapter 的 Composition Root 接入；只有配置
来源、进程生命周期、输出边界和安全负例稳定后，才进入 loopback HTTP。
