# S04 Write + Command 差距报告

## 已理解并验证

S04 已把读取、精确 Patch、新文件创建、前台命令、单次审批、输出限制、取消和进程树
清理组合为第一个可运行 Coding Loop。公开 Fixture 证明模型能够消费失败测试证据后
继续修复，同时越权文件不会因项目指令或模型意图而绕过审批。

## 仍弱于成熟 Harness 的能力

- Permission 只有固定 DEFAULT/PLAN 和 Allow Once/Deny；规则来源、优先级、
  Session Allow 与拒绝恢复属于 S05；
- 没有 Checkpoint、Undo、崩溃恢复和未完成副作用检测，属于 S06；
- 没有自动 Context 压缩，属于 S07；
- Command 没有交互 TTY、持久 Shell、后台执行或 Worktree 隔离，属于 S12；
- Permission 和进程树清理不是 OS Sandbox，文件、进程、网络隔离属于 S13；
- 模型失败已有 `category/statusClass/attempts/receivedOutput` 类型化脱敏摘要，能区分
  5xx、限流、鉴权、网络、超时与不完整流；Provider-specific 指标、Trace 和完整错误治理
  仍属于 S14；
- 当前只有一个 Scripted Seed Task，没有真实模型成功率、成本、重复运行和跨平台
  Eval，属于 S14；
- 已有用户级 `codej` 源码开发 shim，可从调用目录启动现有 TUI/Java Runtime，并以
  内容摘要复用构建；但它仍依赖源码仓库、PowerShell 7、JDK 21 与 Node.js 22，没有
  Runnable Jar、原生二进制、版本更新或正式跨平台安装，`DIST-01/DIST-02` 仍为 L0。
